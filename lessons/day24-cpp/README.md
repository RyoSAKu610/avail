## 1. Rust・Go との違い（3分）

| やりたいこと | Rust | Go | C++ |
| --- | --- | --- | --- |
| アドレスを取る | `&x` | `&x` | `&x` |
| 指す先を読む | `*p` | `*p` | `*p` |
| 何も指さない | （参照にはない。`Option<&T>`） | `nil` | `nullptr` |
| 何も指さないものを読む | コンパイルエラー | panic | **未定義動作**（多くはクラッシュ） |
| ヒープに確保 | `Box::new(x)` | 自動（GC が判断） | `new T(x)` |
| 解放 | 自動（スコープを抜けると） | 自動（GC） | **自分で `delete`** |
| 解放後に使う | コンパイルエラー | 起きない | 未定義動作 |

覚えるのは次の 3 点です。

1. **ポインタは「アドレスを入れる変数」**。`int* p = &x;` で `x` を指し、`*p` で `x` の値を読み書きします。
2. **参照は「付け替えられない別名」、ポインタは「付け替えられて、何も指さないこともある」**。何も指さない可能性があるなら、使う前に `nullptr` かどうかを確認します。
3. **`new` したら `delete` が必要**。忘れるとメモリリーク、2 回やったり解放後に使ったりすると未定義動作です。Rust や Go がコンパイラや GC で防いでいることを、C++ では自分で管理します（Day 27 で楽にする方法を学びます）。

[sample.cpp](sample.cpp) の最初の部分で、`&` と `*` の 2 つの使い方を確認してください。

```cpp
int x = 10;
int* p = &x;  // &x で x のアドレスを取り出す
*p = 20;      // 指している先 (つまり x) を書き換える
```

`&` と `*` は、型の中に書くか式の中に書くかで意味が変わります。型の `int*` は「ポインタ型」、式の `*p` は「指す先の値」、型の `int&` は「参照型」、式の `&x` は「アドレス」です。

## 4. 確認クイズ（2分）

**Q1.** 次のコードの出力は？

```cpp
int a = 1, b = 2;
int* p = &a;
p = &b;
*p = 9;
std::cout << a << " " << b;
```

<details><summary>答え</summary>

`1 9` です。`p` は途中で `b` を指すように付け替えられたので、`*p = 9` で変わるのは `b` です。参照（`int&`）は、このような付け替えができません。

</details>

**Q2.** 次の関数の問題点は？

```cpp
int* makeNumber() {
    int n = 42;
    return &n;
}
```

<details><summary>答え</summary>

関数の中の変数 `n` はスタックにあり、関数を抜けると消えます。消えた変数のアドレスを返しているので、呼び出し元で使うと未定義動作です（ダングリングポインタ）。g++ は `address of local variable 'n' returned` と警告してくれます。Rust ならコンパイルエラーになるケースです。

</details>

**Q3.** スタックとヒープの使い分けは？

<details><summary>答え</summary>

普通の変数（スタック）は速く、関数を抜けると自動で消えます。大きなデータ、関数を抜けたあとも残したいデータ、実行時まで大きさがわからないデータはヒープに置きます。`std::vector` や `std::string` は、中身を自動でヒープに置いて管理してくれます。

</details>

## 日本企業での使われ方

- 組込み系では、メモリが限られているため「実行中に `new` を使わない（起動時にすべて確保する）」というルールのプロジェクトもあります。
- C 言語との境界（古いライブラリや OS の API）では、今でも生のポインタが必ず出てきます。読めることは C++ エンジニアの必須スキルです。
- `nullptr` チェック漏れや解放後の使用は、セキュリティ上の脆弱性にもつながるため、レビューや静的解析ツールで重点的に確認されます。
